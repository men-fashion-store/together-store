# Together

متجر عربي لعرض منتجات العناية واستقبال طلبات الدفع عند الاستلام. لا توجد بوابة دفع، ولا يتم تحويل العميل إلى واتساب.

## المزايا

- كتالوج منتجات وأقسام وعروض وسلة شراء.
- طلبات COD محفوظة في Firebase Realtime Database وتظهر في لوحة الإدارة.
- إدارة المنتجات والنصوص والألوان والعروض من لوحة التحكم.
- إدارة حالات الطلبات وتنبيهات صوتية وإشعارات متصفح عند فتح لوحة الإدارة.
- صور المنتجات تُرفع إلى Firebase Storage من حساب الإدارة.

## متطلبات Firebase

المشروع يستخدم Firebase Web SDK من CDN وبيانات المشروع المضمّنة في `index.html`.

1. فعّل Email/Password في Firebase Authentication.
2. أنشئ حساب الإدارة بالبريد المحدد في `index.html`، ثم أكمل تحقق البريد الإلكتروني.
3. انشر محتوى `database.rules.json` من صفحة Realtime Database → Rules.
4. إعداد Firebase App Check مطلوب قبل استقبال الطلبات: سجّل تطبيق الويب عبر reCAPTCHA v3، ضع **Site Key فقط** في `APP_CHECK_SITE_KEY` داخل `index.html`، واترك Secret Key داخل إعداد Firebase فقط. راقب الطلبات وتأكد من نجاحها قبل تفعيل enforcement.
5. Storage اختياري لرفع الصور. عند تفعيله، انشر `storage.rules` من صفحة Storage → Rules.

لا تستخدم Test mode ولا تضع أي Secret Key أو كلمة مرور في هذا المستودع. إعداد App Check غير مكتمل حاليًا، لذلك إرسال الطلبات متوقف في واجهة الموقع حتى إضافة Site Key.

## النشر على GitHub Pages

من إعدادات المستودع اختر **Pages → Deploy from a branch → main → /(root)**. بعد نشره، أضف نطاق `men-fashion-store.github.io` إلى Authorized domains في Firebase Authentication وإلى نطاقات reCAPTCHA.

## حدود التشغيل الحالية

- لوحة الإدارة تستقبل التحديثات والتنبيهات أثناء فتحها فقط؛ لا توجد إشعارات خلفية أو واتساب آلي.
- الأسعار والمخزون في الطلب هي لقطة مرسلة من المتصفح، ويجب مراجعتها يدويًا قبل التأكيد. لا يتم خصم المخزون تلقائيًا.
- التحقق الموثوق من الأسعار/المخزون والإشعارات عند إغلاق لوحة الإدارة يحتاج خدمة خلفية غير مضمنة هنا.
- قبل استقبال عملاء حقيقيين، اختبر طلبًا كاملًا من الموقع وتأكد من ظهوره في لوحة الإدارة.
